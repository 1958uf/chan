# A 股 ETF 份额与宽基资金动向跟踪：GitHub 项目调研

## 一、调研结论

- 调研日期：2026-10-29。
- 需求：跟踪上证50、沪深300、科创50、创业板等宽基 ETF 的份额变化，结合盘中异常观察潜在大资金动向。
- 结论：GitHub 上有相关项目。本轮下载了三个项目：**AKShare（数据底座）**、**national-team-position（份额趋势图）**、**Resonance / 同频（盘中量价与日频份额看板）**。

### 必须先明确的口径

1. **实时行情不等于实时份额。** 盘中价格、成交额、折溢价可以轮询，交易所 ETF 份额按日统计并披露，通常需要等待发布。始终显示统计日期和采集时间，不能将旧份额贴上实时标签。
2. **ETF 总份额不等于国家队持仓。** 总份额变化包含个人、其他机构、套利盘等申购赎回；无法从公开份额数据确定具体买方身份。
3. **二级市场买卖不一定改变份额。** 大资金可在场内买入存量 ETF，而不发生净申购；份额不变不能证明大资金没有动作。
4. **持有人披露不能实时使用。** 十大持有人及汇金等机构持有份额主要来自报告期披露，通常为半年报、年报口径，应分别记录报告期、公告日和采集时间；不能回填成当时已知信息。
5. **规则评分不是经过校准的概率。** 项目输出的“国家队买入概率”属于启发式评分，不能理解为真实机构身份识别概率。

## 三、逐项目评估

### 1. AKShare：首选数据底座

**功能**：通用财经数据接口库，当前版本已包含沪深交易所 ETF 日份额和 ETF 行情接口。它不是现成的国家队监控看板，但最适合构建可靠的数据采集层。

| 接口 | 用途 | 日期能力 | 已核实源码 |
| --- | --- | --- | --- |
| `fund_etf_scale_sse(date=...)` | 上交所全部 ETF 份额 | 指定统计日 | `extension/akshare/akshare/fund/fund_etf_sse.py` |
| `fund_etf_scale_szse()` | 深交所 ETF 当前份额列表 | 最新快照，没有历史日期参数 | `extension/akshare/akshare/fund/fund_etf_szse.py` |
| `fund_scale_daily_szse(start_date=..., end_date=..., symbol="ETF")` | 深交所基金规模日频数据 | 指定历史日期区间，文档要求单次范围不超过 6 个月 | `extension/akshare/akshare/fund/fund_scale_szse.py` |
| `fund_etf_spot_em()` | 东方财富 ETF 行情 | 行情快照，含数据日期和更新时间 | `extension/akshare/akshare/fund/fund_etf_em.py` |
| `fund_etf_hist_min_em(...)` | ETF 分钟行情 | 历史分钟价格及成交数据，不是分钟份额 | 同上 |

**单位**：上交所原始 `TOT_VOL` 为万份，AKShare 乘 `10000` 转为份；深交所上述 Excel 接口原始列为份。不要将另一种深市接口的 `current_size` 单位直接套用到 Excel 列。

**注意**：上交所函数当前默认参数仍是固定示例日期 `20250115`，必须显式传入要查询的日期，并核对返回的统计日期。东财“最新份额”只是字段名，不保证随盘中实时更新；行情端点也可能延迟。

**参数和使用示例**（以下仅为后续评估示例，本轮未执行）：

```python
import akshare as ak

# 上交所：指定统计日，返回全市场 ETF 日份额。
sse = ak.fund_etf_scale_sse(date="20261028")

# 深交所：指定日期范围，可查询创业板等深市 ETF 历史日份额。
szse = ak.fund_scale_daily_szse(
    start_date="20261027", end_date="20261028", symbol="ETF"
)

# 深交所：最新份额快照，不能用这个无日期参数的接口回补历史。
szse_latest = ak.fund_etf_scale_szse()

# 行情只作盘中辅助，不能把“最新份额”当作实时申赎。
spot = ak.fund_etf_spot_em()
```

后续需要独立 Python 环境并按照上游要求安装依赖；当前只完成源码下载和原始上游抽查，没有安装 AKShare。

### 2. national-team-position：宽基历史趋势参考

**功能**：按上交所宽基 ETF 份额采样，生成六合一总图、六张指数单图和 JSON；份额曲线与指数价格分开展示。

- 覆盖：沪深300、上证50、中证500、中证1000、中证A500、科创50。
- 采样：`weekly` 或 `monthly`，**不是日频实时监控**。
- 来源：AKShare 上交所份额与指数日线。
- 当前没有深市采集，因此**不覆盖创业板 ETF、嘉实沪深300 ETF 159919 等深市产品**。
- 脚本中的代码分组是选定产品，不是每个指数的全市场所有 ETF；跨产品原始份额加总不能直接代表国家队总持仓或资金金额。
- README 对“深市没有公开历史份额”的说明已不适用于本次核实结果：AKShare 当前有 `fund_scale_daily_szse`，其上游历史接口本轮实测成功。不能据此把上游原项目认定为已经支持深市。

**源码**：`extension/national-team-position/scripts/national_team_position.py`。

**参数**：`--start`、`--end` 为日期范围；`--freq` 为 weekly/monthly；`--output-dir` 为输出路径；`--data-only` 只输出 JSON。

**后续手动评估命令**（从主工程根目录执行，需先准备独立环境，本轮未执行）：

```powershell
python extension/national-team-position/scripts/national_team_position.py --start 2026-09-01 --end 2026-10-28 --freq weekly --data-only --output-dir extension/national-team-position/output
```

不需要将这个仓库安装到 Claude 技能目录，本轮也没有这样做。其“国家队持仓估计”名称仅为项目自述，输出应标为宽基 ETF 份额代理指标。

### 3. Resonance / 同频：最接近盘中看板，但需补全覆盖并验证

**功能**：FastAPI、React、SQLite 的本地监控系统，结合价格位置、份额流向、交易方向、成交额热度、融资杠杆展示信号，带历史图、数据管理和 CLI 摘要。

**已核实源码**：

- `backend/base/config.py`：ETF 清单、阈值、30 秒行情轮询间隔、数据库路径。
- `backend/base/fetch/shares.py`：上交所按日份额、AKShare 深交所历史日份额、最近可用日期回退和份额变化计算。
- `start.sh`、`start-prod.sh`、`frontend/vite.config.ts`：启动和监听范围。

**频率**：约 30 秒更新的是行情及信号。份额仍使用最近发布的日数据，并记录对应日期；它不是逐笔实时申赎系统。

**默认覆盖限制**：当前配置有上证50、沪深300、中证500、中证1000、科创50、A500等，但没有默认加入创业板 `159915`、创业板50 `159949`，也没有完整覆盖多只沪深300 ETF。测试文件出现某代码不表示默认监控已经包含它。要满足本需求，需要增加标的并验证数据、策略路由与前端支持，而不是只改一个列表就宣称完成。

**配置参数**：`ETF_MONITOR_HOME` 指定本地数据库工作目录；`REALTIME_INTERVAL_SEC` 当前为 `30`；ETF 清单及评分阈值见上游配置文件。

**后续本地启动示例**（需要独立环境及前后端依赖；本轮未执行）：

```powershell

# 前端：在 extension/Resonance/frontend 中执行。
```

前端地址以启动输出为准。启动前应先解决许可、依赖、安全监听和缺失标的问题；默认上游 Bash 一键启动脚本不应直接作为 Windows 主工程启动方式。

### 建议分三层监控

1. **盘中线索层**：分时成交额、同时间段量比、价格/IOPV折溢价、多只同指数ETF同步异动，输出“异常成交提示”，不直接贴国家队标签。
2. **日份额验证层**：两市日份额、份额变化、5/20日累计变化，公布实际统计日期、采集时间和缺失状态。
3. **机构披露层**：持有人名称、报告期、公告日、披露持有份额，作为身份佐证；不插值为每日实际持仓。

**估算净申赎金额**应逐只ETF使用 `份额变化 × 对应日期单位净值`，再按指数汇总，并清楚标为估算。不能用资产规模日差直接当净流入，也不能将不同ETF原始份额简单加总后当金额。缺失、估算、插值数据应分别标记，缺失不填成零。
