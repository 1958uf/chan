## 四、详细需求

### RF-001：修复 GUI 绘图旧导入

**问题与依据**

- `App/ashare_bsp_scanner_gui.py:679` 的 `plot_chart()` 仍使用 `from Plot.PlotDriver import CPlotDriver`。
- 绘图模块已迁入 `Strategies/chan/Plot/`，正常项目路径下该旧导入失效；即使股票分析成功，也无法正常绑定图表。
- 当前异常由同文件 `706—707` 行弹窗处理。

**修复要求**

1. 将绘图依赖指向迁移后的模块。
2. 检查 GUI 内延迟导入、函数内部导入是否还有同类残留。
3. 不通过人为添加旧目录到搜索路径掩盖迁移遗漏。

**验收标准**

- GUI 能完成单股分析、图表绑定和刷新，显示 K 线、笔、线段、中枢等既有元素。
- 不出现旧 `Plot` 模块找不到的错误。
- 图表重复刷新仍正常，原有交互行为保持兼容。

### RF-003：修复缠论回测新增买卖点识别

**问题与依据**

- `Strategies/chan/chan_strategy.py:79—96` 仅在买卖点总数增加时处理信号，并且数量下降时没有同步更新记录。
- `Strategies/chan/BuySellPoint/BSPointList.py:44—53、100—105` 会删除并重新计算未确认买卖点，买卖点集合不是只增不减。
- 纯内存桩复现：数量依次为 `1 → 0 → 1`，第一次买点触发买入，旧点删除后出现新卖点，实际仅发生买入，新卖点未处理。

**修复要求**

1. 新信号识别不能只依赖集合长度，应能区分买卖点新增、删除、替换和类型变化。
2. 明确可交易信号的确认时机、信号身份和去重规则，避免漏单或重复下单。
3. 保持逐 K 线推进，不使用未来数据预先生成交易信号。
4. 不将“数量下降时重置计数”作为完整修复依据；同数量替换等情况也应覆盖。

**验收标准**

- 覆盖数量增长、下降、同数量替换、删除后新增、同一信号重复出现等测试。
- `1 → 0 → 1` 的已复现场景不再遗漏新卖点。
- 使用固定行情逐步对照适配器和直接步进 `CChan` 的买卖点变化；交易行为符合文档约定的确认与去重规则。

### RF-004：修复资金不足的买入边界

**问题与依据**

- `Backtest/broker.py:59—81` 在手续费超过可用资金时仍计算买入数量，可能产生负数。
- 纯内存实测：初始资金 `1`，调用 `buy()`、价格 `10`，默认最低手续费 `5`，产生 `-0.4` 的持仓。

**修复要求**

1. 下单前检查可用现金是否足以承担成交金额和手续费。
2. 拒绝无法成交的买入，不生成负数量持仓或虚假交易记录。
3. 明确初始资金、价格、数量和手续费参数的有效范围，处理不合法输入。
4. 保持资金、持仓、手续费和交易记录相互一致。

**验收标准**

- 初始资金 `1`、价格 `10` 的场景不能形成负持仓。
- 覆盖零资金、低于最低手续费、临界资金、正常全仓及指定数量买入。
- 拒绝订单不扣除成交费用，不写入成交记录；正常订单不会导致超支。
