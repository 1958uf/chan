# Chan 项目量化能力评估报告

> 评估日期：2026-07-17
> 评估对象：`D:\xuquanqing\persion\Chan`（基于开源 chan.py / Vespa314 二次开发）
> 评估目的：判断当前项目是否具备一个完整量化交易系统所需的数据、策略、回测、评估、执行与风控、工程化等能力，并给出后续优化方向。

---

## 一、总体定位

这是一个基于开源 **chan.py（Vespa314）** 二次开发的项目。核心是**缠论静态计算 + 买卖点扫描**，在开源版基础上增加了：

- BaoStock 本地 K 线缓存与增量更新
- 股票池批量扫描
- PyQt6 GUI 扫描器（`App/ashare_bsp_scanner_gui.py`）
- 终端交互查询（`main.py` REPL）

**核心结论：它目前是一个"信号扫描 / 选股工具"，还不是完整的量化交易系统。**

公开版代码约 5300 行，完整版约 22000 行（README 与 `kaifa.md` 说明：开源部分**不含**策略类、特征、模型、AutoML、交易引擎对接）。

## 二、逐项能力评估

| 模块 | 现状 | 完备度 |
|------|------|--------|
| **数据层** | BaoStock（A股日K）、Akshare（备用/实时）、ccxt（加密货币）、CSV（本地缓存）、`CommonStockAPI` 抽象基类；支持前复权 `AUTYPE.QFQ`；`chan_cache/` 本地 CSV 缓存 + 增量更新机制 | 🟢 较好 |
| **策略层（缠论核心）** | 缠论元素计算**完整**：笔(Bi)、线段(Seg)、中枢(ZS)、买卖点(1/2/3类及变种 1p/2s/3a/3b)；`ChanConfig` 可配置参数；`Math/` 含 MACD/BOLL/KDJ/RSI/TrendLine/Demark | 🟢 缠论核心强 |
| **策略类（交易逻辑）** | 仅有 `Debug/strategy_demo*.py` 共 6 个演示，属"极弱智策略"样例；**无成型策略框架、无仓位 / 择时 / 选股组合逻辑** | 🔴 缺失 |
| **机器学习 / 特征** | `ChanModel/Features.py` 仅是特征容器（dict 包装），**无特征工程、无模型、无 AutoML**（README 明确说明公开版不含） | 🔴 缺失 |
| **回测** | `strategy_demo.py` 用 `chan.step_load()` 逐 K 线模拟买卖，**仅为示意**；无回测引擎、无资金曲线、无滑点手续费、无成交撮合 | 🔴 缺失 |
| **评估** | `check.md` 为扫描输出表；**无收益 / 夏普 / 最大回撤 / 胜率 / 盈亏比等指标计算**，无评估报告 | 🔴 缺失 |
| **执行（下单）** | **完全没有**券商接口、无模拟盘 / 实盘对接、无订单管理 | 🔴 缺失 |
| **风控** | **完全没有**止损止盈、仓位控制、最大回撤限制、黑名单等 | 🔴 缺失 |
| **工程化** | ✅ 模块化目录清晰、配置驱动(`CChanConfig`)、本地缓存 + 增量更新、BaoStock 登录重试 / 断线重连、进度显示、GUI、`run.bat` 一键启动、`stock_pool.txt` 股票池 | 🟡 基础有，进阶缺 |
| **日志 / 监控** | 使用 `print` + `sys.stdout.write`；**无 logging 模块、无日志文件、无告警** | 🟡 弱 |
| **测试** | **无单元测试、无 pytest**（CLAUDE.md 要求核心逻辑有测试覆盖） | 🔴 缺失 |
| **定时调度** | 无 APScheduler / cron；`main.py` 为交互式 REPL，非服务化 | 🔴 缺失 |

## 三、结论一句话

**数据 + 缠论计算（策略的"原料"）很强；但从"信号"到"交易"的整条链路——策略框架、回测、评估、执行、风控——基本是空的。**

- **强项**：缠论元素计算的工程质量不错，数据缓存和扫描流程实用。
- **缺口**（按优先级）：
  1. **回测引擎**（验证策略有效性，是后续一切的前提）
  2. **评估指标库**（收益 / 夏普 / 回撤 / 胜率）
  3. **策略框架**（把 demo 升级为可配置、可组合的策略基类）
  4. **风控**（止损 / 仓位 / 最大回撤）
  5. **执行对接**（模拟盘 → 实盘）
  6. **工程化补强**（logging、测试、定时调度）

## 五、推荐下一步：从「回测引擎 + 评估指标」起步

这是性价比最高的一步——能立刻让现有的缠论买卖点信号变成可量化验证的策略，也为后续风控和执行打下基础。

建议方案（待确认后实施）：

- 基于现有 `CChan.step_load()` 逐 K 线接口，实现一个**轻量事件驱动回测器**
- 配套**评估指标库**：年化收益、夏普、最大回撤、胜率、盈亏比、单笔最大亏损等
- 产出**资金曲线 + 交易明细 + 评估报告**（可复用 `Plot/` 出图）
- 不改动现有缠论核心代码，作为新增模块接入

> 后续可按优先级逐步补齐：策略框架 → 风控 → 执行对接 → 工程化（logging / 测试 / 定时调度）。
