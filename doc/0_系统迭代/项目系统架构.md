## 一、整体架构概览

项目是一个**缠论量化分析框架**，核心是"取数据 → 逐层计算缠论元素 → 输出买卖点信号"的流水线。

### 分层架构

```
┌─────────────────────────────────────────────────────────┐
│  入口层   main.py（终端）  App/（GUI）  Plot/（画图）     │
├─────────────────────────────────────────────────────────┤
│  调度层   Chan.py（CChan 调度核心）  ChanConfig.py       │
├─────────────────────────────────────────────────────────┤
│  计算层   BuySellPoint ← ZS ← Seg ← Bi ← KLine/Combiner │
│          辅助：Math/（指标）  ChanModel/（特征）          │
├─────────────────────────────────────────────────────────┤
│  数据层   DataAPI/（BaoStock/Akshare/ccxt/CSV/SQLite）   │
│          Common/（枚举/异常/时间/工具/缓存）              │
└─────────────────────────────────────────────────────────┘
```

### 数据流向

```
DataAPI(取K线) → KLine/Combiner(K线合并) → Bi(笔) → Seg(线段) → ZS(中枢) → BuySellPoint(买卖点)
                                                                            ↓
                                                        main.py/App/Plot 输出
```

### 3.3 计算链（CKLine_List 驱动）

**`KLine/KLine_List.py` 的 `CKLine_List`** 是计算链的核心容器，它把所有缠论元素串起来：

```
CKLine_List
  ├── Combiner/KLine_Combiner  ← K线包含合并（产出独立K线）
  ├── Bi/BiList                ← 笔的计算（基于合并后的K线分型）
  ├── Seg/SegListChan          ← 线段的计算（基于笔 + 特征序列）
  ├── ZS/ZSList                ← 中枢的计算（基于笔/段的重叠）
  └── BuySellPoint/BSPointList ← 买卖点的计算（基于中枢 + 背驰）
```

**层层依赖关系**（自底向上）：

```
KLine_Unit（单根K线）
  ↑ 被
Combiner（K线合并）
  ↑ 产出分型，被
Bi/BiList（笔）
  ↑ 被
Seg/SegList（线段，依赖 BiList + Eigen特征序列）
  ↑ 被
ZS/ZSList（中枢，依赖 Bi + Seg）
  ↑ 被
BuySellPoint/BSPointList（买卖点，依赖 Bi + Seg + ZS）
```

#### 3.3.1 CKLine_List 的核心数据结构（KLine/KLine_List.py:35）

`CKLine_List` 在构造时一次性创建所有子模块的容器，形成完整的计算链：

```python
class CKLine_List:
    def __init__(self, kl_type, conf):
        self.lst: List[CKLine] = []           # K线列表（合并后的独立K线）
        self.bi_list = CBiList(...)           # 笔列表
        self.seg_list = ...                   # 线段列表（基于笔）
        self.segseg_list = ...                # 线段线段列表（基于线段，更高一级）
        self.zs_list = CZSList(...)           # 笔中枢列表
        self.segzs_list = CZSList(...)        # 段中枢列表
        self.bs_point_lst = CBSPointList(...) # 笔买卖点
        self.seg_bs_point_lst = CBSPointList(...)  # 段买卖点
        self.metric_model_lst = conf.GetMetricModel()  # 指标模型（MACD/BOLL等）
        self.step_calculation = conf.trigger_step     # 是否逐K线回放模式
```

**关键设计**：双级别计算。`seg_list`/`zs_list`/`bs_point_lst` 基于**笔**；`segseg_list`/`segzs_list`/`seg_bs_point_lst` 基于**线段**（把线段当作"大笔"再算一次中枢和买卖点），实现多级别联立。

#### 3.3.2 计算触发：逐K线 vs 批量（add_single_klu）

数据通过 `add_single_klu(klu)` 逐根喂入。每来一根K线：

```python
def add_single_klu(self, klu):
    klu.set_metric(self.metric_model_lst)     # 1. 算指标（MACD/BOLL/KDJ等）
    if 首根:
        self.lst.append(CKLine(klu, idx=0))
    else:
        _dir = self.lst[-1].try_add(klu)      # 2. K线包含合并（Combiner）
        if _dir != COMBINE:                    # 不合并 → 新增独立K线
            self.lst.append(CKLine(klu, ...))
            self.lst[-2].update_fx(...)        # 3. 顶底分型判定（需要前后3根）
            if self.bi_list.update_bi(...) and self.step_calculation:
                self.cal_seg_and_zs()          # 4. 逐K线模式：立即算段/中枢/买卖点
```

**两种模式**：

- **批量模式**（`trigger_step=False`，默认扫描用）：所有K线喂完后，`cal_seg_and_zs()` 一次性算完
- **逐K线模式**（`trigger_step=True`，回测/回放用）：每形成一笔就触发完整计算，可回放历史信号

#### 3.3.3 完整计算顺序（cal_seg_and_zs，KLine_List.py:104）

这是整个缠论计算的核心调度，顺序严格依赖：

```python
def cal_seg_and_zs(self):
    # ① 笔 → 线段
    cal_seg(self.bi_list, self.seg_list, ...)
    # ② 笔 + 线段 → 笔中枢
    self.zs_list.cal_bi_zs(self.bi_list, self.seg_list)
    # ③ 把中枢归属到线段，并标记中枢的进入笔(bi_in)/离开笔(bi_out)
    update_zs_in_seg(self.bi_list, self.seg_list, self.zs_list)

    # ④ 线段 → 线段线段（更高一级，把线段当笔再算一次）
    cal_seg(self.seg_list, self.segseg_list, ...)
    # ⑤ 线段 + 线段线段 → 段中枢
    self.segzs_list.cal_bi_zs(self.seg_list, self.segseg_list)
    # ⑥ 段中枢归属到线段线段
    update_zs_in_seg(self.seg_list, self.segseg_list, self.segzs_list)

    # ⑦ 段买卖点（先算高级别）
    self.seg_bs_point_lst.cal(self.seg_list, self.segseg_list)
    # ⑧ 笔买卖点（再算低级别）
    self.bs_point_lst.cal(self.bi_list, self.seg_list)
```

**顺序要点**：笔→段→笔中枢→段→段中枢→（段买卖点→笔买卖点）。高级别买卖点先于低级别计算，便于低级别参考高级别结果。

#### 3.3.4 增量计算优化（last_sure_*_idx）

为支持逐K线回放且避免全量重算，`CKLine_List` 维护"最后确定位置"游标：

- `last_sure_seg_start_bi_idx`：最后一段**已确定**线段的起始笔索引
- `last_sure_segseg_start_bi_idx`：线段线段同理

`cal_seg()`（KLine_List.py:142）只从这个游标之后重新计算，已确定部分跳过。`ZSList` 也有 `last_sure_pos`/`last_seg_idx` 做同样的事。这是性能关键 —— 回放模式下不必每根K线全量重算。

### 3.3a 线段计算与特征序列（Seg/EigenFX）

线段判定是缠论最复杂的一环，核心在 `Seg/SegListChan.py` + `Seg/EigenFX.py`。

#### 线段算法选择（get_seglist_instance）

```python
seg_algo == "chan"   → CSegListChan   # 缠论标准算法（推荐，特征序列分型）
seg_algo == "1+1"    → CSegListDYH    # 已废弃
seg_algo == "break"  → CSegListDef    # 已废弃
```

默认用 `chan` 算法。

#### 特征序列分型（CEigenFX）—— 线段判定的核心

线段是否结束，靠**特征序列的分型**判定。`CEigenFX` 维护三个元素 `ele[0], ele[1], ele[2]`（类似K线的顶底分型，但作用对象是"特征序列"）：

```python
class CEigenFX:
    def __init__(self, _dir):
        self.ele: List[CEigen] = [None, None, None]  # 三元素
        self.dir = _dir        # 线段方向（UP/DOWN）
        self.lst: List[CBi] = []  # 参与判定的笔
```

**判定流程**（每来一笔 `bi`）：

1. **第一元素** `treat_first_ele`：以当前笔构造 `ele[0]`
2. **第二元素** `treat_second_ele`：尝试合并到 `ele[0]`，不能合并则作为 `ele[1]`
   - 若前两元素已不可能成分形（上升段中 `ele[1].high < ele[0].high`），`reset()` 重置
3. **第三元素** `treat_third_ele`：构造 `ele[2]`，判定**真实突破** `actual_break()`
   - 三元素成形 + 真实突破 → 特征序列分型成立 → **线段结束**

**方向配对**（SegListChan.py:36）：

- 上升线段看**下降笔**的特征序列（`up_eigen`）
- 下降线段看**上升笔**的特征序列（`down_eigen`）

```python
if bi.is_down() and last_seg_dir != UP:
    if up_eigen.add(bi):      # 上升线段的下降笔特征序列
        fx_eigen = up_eigen
```

#### 不确定线段回滚（do_init）

每次 `update` 前先 `do_init()`：删除末尾**未确定**的线段，从最后一个确定线段之后重算。这保证逐K线回放时，未完成的线段会被持续修正，已确定的线段稳定不变。

### 3.3b 中枢计算（ZS/ZSList）

#### 中枢构造（CZSList）

中枢 = 至少连续三段（笔）有价格重叠的区间。`ZSList` 用"自由笔列表" `free_item_lst` 累积候选：

```python
def update(self, bi, is_sure=True):
    if 空且能加到末尾:
        try_combine()             # 尝试与已有中枢合并
    else:
        add_to_free_lst(bi, ...)  # 加入候选
        # try_construct_zs: 3段重叠 → 成中枢
        if 成中枢 and begin_bi.idx > 0:  # 禁止第一笔即中枢起点
            self.zs_lst.append(zs)
            try_combine()
```

#### 中枢的关键属性（update_zs_in_seg）

中枢归属到线段时，标记三类笔：

| 属性       | 含义                                | 作用                 |
| ---------- | ----------------------------------- | -------------------- |
| `bi_in`  | 进入中枢的笔（`begin_bi` 前一笔） | 判断背驰的"参照段"   |
| `bi_out` | 离开中枢的笔（`end_bi` 后一笔）   | 判断背驰的"被比较段" |
| `bi_lst` | 中枢内部的笔                        | 中枢范围             |

**买卖点的背驰判定**就依赖 `bi_in` vs `bi_out` 的力度对比（MACD 面积/峰值）。

### 3.3c 买卖点计算（BuySellPoint/BSPointList）

#### 买卖点类型与含义

| 类型        | 含义         | 判定依据                                       |
| ----------- | ------------ | ---------------------------------------------- |
| `1B/1S`   | 一类买卖点   | 趋势背驰（离开中枢笔 vs 进入中枢笔 MACD 背驰） |
| `1pB/1pS` | 盘整背驰一类 | 盘整背驰（非趋势背驰，更弱）                   |
| `2B/2S`   | 二类买卖点   | 一类后反向一笔再回抽确认                       |
| `2sB/2sS` | 类二买卖点   | 二类的变种                                     |
| `3aB/3aS` | 三类买卖点a  | 中枢出现在一类后面                             |
| `3bB/3bS` | 三类买卖点b  | 中枢出现在一类前面                             |

#### 计算入口（cal 方法）

```python
self.bs_point_lst.cal(self.bi_list, self.seg_list)    # 笔买卖点
self.seg_bs_point_lst.cal(self.seg_list, self.segseg_list)  # 段买卖点
```

`CBSPointList` 是泛型类（`Generic[LINE_TYPE, LINE_LIST_TYPE]`），同一套逻辑既算笔买卖点（`LINE=CBi`）又算段买卖点（`LINE=CSeg`）。

#### 存储与迭代

```python
bsp_store_dict: Dict[BSP_TYPE, (买点列表, 卖点列表)]  # 按类型+方向分类存储
bsp_store_flat_dict: Dict[bi_idx, CBS_Point]          # 按笔索引扁平索引
```

`bsp_iter()` 按类型遍历输出所有买卖点。增量计算时 `clear_store_end()` 会删除"未确定"的尾部买卖点，待重算。

#### 买卖点判定依赖链

```
CBS_Point
  ├── 依赖 CZS（中枢）：bi_in / bi_out / 中枢区间
  ├── 依赖 CBi（笔）：背驰的两段
  ├── 依赖 CSeg（线段）：高级别方向参考
  └── 依赖 CFeatures（特征）：背驰力度（MACD面积/峰值，来自 Math/CMACD）
```

**一类买卖点核心逻辑**：`bi_out`（离开中枢的笔）创新高/低，但 MACD 力度 < `bi_in`（进入中枢的笔）→ 背驰 → 一类买卖点。MACD 力度由 `Math/CMACD` 提供，算法由 `ChanConfig.macd_algo` 决定（`peak`/`area`/`full_area` 等）。

## 六、数据层抽象设计（重点）

所有数据源继承 `CCommonStockApi`，实现统一接口，`CChan` 通过 `DATA_SRC` 枚举分发，**对上层完全透明**：

```python
class CCommonStockApi:
    def get_kl_data(self) -> Iterable[CKLine_Unit]:  # 子类实现：yield K线
        ...
    def SetBasciInfo(self):                          # 设置股票名称等
        ...
    @classmethod
    def do_init(cls): ...                            # 类初始化（如登录）
    @classmethod
    def do_close(cls): ...                           # 类清理（如登出）
```

**新增数据源只需 3 步**（本次 SQLite 即如此）：

1. `CEnum.py` 的 `DATA_SRC` 加枚举值
2. 新建 `DataAPI/XxxAPI.py` 实现 `Xxx_API(CCommonStockApi)`
3. `Chan.py:GetStockAPI()` 加分发分支

**对缠论核心（KLine/Bi/Seg/ZS/BuySellPoint）零侵入。**

## 七、SQLite 缓存层设计（本次新增）

### 7.1 读写分离

| 组件                | 职责                                       | 调用方                     |
| ------------------- | ------------------------------------------ | -------------------------- |
| `ChanSqliteCache` | **写**：建表、增量更新、去重、元信息 | `main.py`（扫描/查询前） |
| `SQLite_API`      | **读**：`get_kl_data()` 读取 K 线  | `CChan`（计算时）        |

### 7.2 数据库结构（`chan.db`）

- **kline 表**：主键 `(code, k_type, date, autype)`，含 OHLC + volume/turnover/turnrate
- **stock_meta 表**：股票名称/板块/最后更新日期
- 索引：`(code, k_type, autype, date)` 支持区间查询

### 7.3 增量更新流程

```
ChanSqliteCache.update(code, begin_time)
  ├── SELECT MAX(date) 查最后日期
  ├── 从次日起 baostock 拉取
  ├── 跳过停牌空行
  └── 事务内 INSERT OR REPLACE（原子、去重）
```
