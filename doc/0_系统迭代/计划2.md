# 四维共振交易体系 —— 代码落地计划

> 本文档基于对仓库 `chan.py` 的能力评估，规划如何用编程补齐"四维共振交易体系"所需的全部缺口。
> 状态：**规划草案**（后续迭代升级）。
> 编写日期：2026-07-21。

---

## 一、背景与结论

### 1.1 体系的核心逻辑
> 选股靠硬指标排除雷区，开仓靠大盘环境开关，买点靠次日尾盘过滤假突破，持仓靠时间止损不耗，卖出靠筹码衰减硬规则不猜。

体系四维：
1. **筹码维**（定主力）—— 灵魂
2. **量价维**（定力度）
3. **K线+位置维**（定真假）—— 仓库已有强项
4. **板块/市场强弱维**（定环境）

### 1.2 代码现状结论
- 缠论结构维（笔/段/中枢/买卖点）：**已实现，强项**
- 量价维：**部分**（有原始量/额/换手，缺规则模块）
- 筹码维：**零实现**
- 板块/市场强弱维：**零实现**
- 基本面/资金面排雷：**仅换手率一项**
- 回测/仓位/止损执行层：**无引擎，仅 demo 循环**

### 1.3 总判断
**全部缺口均可通过编程实现。** 90% 是"akshare 取数 + 自己写算法"的常规工程活，筹码甚至有现成接口（`stock_cyq_em`）。唯一真正有架构门槛的是"盘中 T+1 二次确认"——需要把框架从"日级 step_load"改造为"日内实时驱动 + 信号状态机"。

## 三、两个关键真相（必须先理解）

### 真相 1：筹码分布有现成接口
- akshare 提供 `stock_cyq_em`（东方财富筹码分布），返回：
  - 90% / 70% 成本集中度
  - 获利盘比例
  - 平均成本
  - 各价位筹码分布
- 体系中的"底部单峰密集""顶格峰衰减5%""获利盘比例"基本可直接取数计算，**无需自己从分笔数据估**。
- **限制**：akshare 筹码为当前快照。要判断"底部单峰形成>3个月"等历史演化，必须**每日定时落库累积**（自建 `chip_dist` 表按日存储）。不累积则无法做3个月回看。
- **行动**：需优先建表，否则历史筹码判断做不了。

### 真相 2：盘中时间逻辑是最大改造点
- 体系要求：14:30 确认阳线 / 次日14:50 二次确认 / 集合竞价斩仓。
- 逻辑本身不难（状态机 + 定时器），难在架构：当前 `chan.py` 为"日级别 step_load"架构（见 `Debug/strategy_demo.py` 逐根日K喂入），**非盘中实时轮询设计**。
- 实现 T+1 二次确认需新增：
  1. 盘中行情轮询层（akshare `stock_zh_a_spot_em` 实时快照，或接券商 L2）
  2. 信号状态机：Day1 放量阳线 → 记录"待确认" → Day2 14:50 检查站稳平台 → 触发买入
  3. 与现有日级缠论分析对接（缠论用日K，盘中确认用实时价）
- 这是**架构改造**，工作量最大。

## 四、落地顺序与分档

建议总顺序：**C → A → B → D**（先灵魂后骨架）。下面按可落地速度分三档。

### 第一档：1-3 天（纯取数 + 纯算法，不动架构）
- 流通市值、股东户数、解禁、大宗交易 → 新建 4 个 akshare 适配器，挂进 `DataAPI/`
- 60日均量线、倍量、缩量、地量 → 在 `Math/` 加 `VolumeAnalyze.py`，输入 volume 序列
- 筹码衰减监测 → 一个函数，输入每日筹码峰序列

### 第二档：1-2 周（建模型 + 改持仓循环）
- 筹码分布接入 + 历史累积表（`stock_cyq_em` 每日落库）
- 止损止盈 → 新建 `Account/Position` 模块，挂 -5% 硬止损、5日/10日时间止损
- 大盘环境联动平仓 → 大盘20日线判断接进持仓循环

### 第三档：最难（动架构）
- 盘中14:30 / 次日14:50 / T+1 二次确认引擎 → 盘中实时驱动层 + 信号状态机

## 五、分模块详细计划

### 模块 C：筹码分布模块（体系灵魂，最先做）

#### C1. 数据接入：akshare `stock_cyq_em`
- 功能：获取个股当日筹码分布快照
- 输入：股票代码
- 输出：获利盘比例、平均成本、90%/70%集中度、价位分布序列
- 落点：新建 `DataAPI/ChipAPI.py`

#### C2. 历史筹码落库
- 功能：每日定时拉取全市场筹码快照，存入 SQLite
- 表结构（新建 `chip_dist` 表）：
  - `code / date / profit_ratio / avg_cost / cost_90 / cost_70 / peak_price / peak_ratio / dist_json`
- 落点：扩展 `DataAPI/sqlite_cache.py`
- **依赖**：必须先建表并累积，否则历史筹码判断（>3个月单峰）无法实现

#### C3. 筹码规则函数
- 功能：判断底部单峰密集、顶格峰衰减、获利盘比例
- 落点：新建 `ChanModel/ChipRule.py`
- 规则：
  - 底部单峰密集：集中度 + 期间累计换手>200% + 形成时间>3个月
  - 顶格峰衰减：peak_ratio 连续5日累计下降>5%
  - 获利盘比例：直接取 `profit_ratio`

#### C4. 筹码衰减监测
- 功能：连降5日>5% 触发减仓信号
- 落点：`ChanModel/ChipRule.py` 内函数
- 输入：每日 peak_ratio 序列

---

### 模块 A：量能四件套（纯算法，最快出成果）

#### A1. 60日均量线
- 功能：计算 volume 的 60 日均值
- 输入：volume 序列
- 输出：每日 60 日均量值
- 落点：新建 `Math/VolumeAnalyze.py`

#### A2. 倍量
- 功能：当日量 >= 前一日量 × 1.8（体系要求 1.8-2 倍以上）
- 输入：volume 序列
- 输出：布尔 + 倍数

#### A3. 缩量
- 功能：当日量 < 第一波反弹均量 × 0.6
- 输入：volume 序列 + 基准均量
- 输出：布尔

#### A4. 地量
- 功能：量能萎缩至 60 日均量线 50% 以下
- 输入：volume 序列
- 输出：布尔

#### A5. 接入 BSP
- 功能：把量能规则作为 BSP 的前置过滤/共振条件
- 落点：`BuySellPoint/BSPointConfig.py` 扩展

---

### 模块 B：基本面排雷数据层

#### B1. 流通市值
- 接口：akshare `stock_zh_a_spot_em`（快照含流通市值）或 `stock_individual_info_em`
- 功能：取流通市值，判断 >50亿
- 落点：`DataAPI/FundamentalAPI.py`

#### B2. 股东户数
- 接口：akshare `stock_zh_a_gdhs` / `stock_zh_a_gdhs_detail_em`
- 功能：取最近季报户数，判断连续2季减少
- 落点：`DataAPI/FundamentalAPI.py`
- 限制：季频，季报后更新

#### B3. 限售解禁
- 接口：akshare `stock_restricted_release_*`
- 功能：取未来3月解禁股本，判断占流通股本>3%
- 落点：`DataAPI/FundamentalAPI.py`

#### B4. 大宗交易
- 接口：akshare `stock_dzjy_*`
- 功能：取近7日大宗，判断折价 + 占比；近1月折价>5%且占比>30%拉黑
- 落点：`DataAPI/FundamentalAPI.py`
- 限制：T+1 公布，非实时

#### B5. 选股前置过滤器
- 功能：把 B1-B4 + 换手率 + 筹码峰有效性串成"排雷清单"，逐项打勾
- 落点：新建 `ChanModel/PreFilter.py`

---

### 模块 D：账户/仓位/止损骨架

#### D1. 账户与仓位对象
- 功能：资金、持仓、订单的统一模型
- 落点：新建 `Account/Account.py`、`Account/Position.py`
- 字段：现金、持仓数量、成本价、买入日期、浮盈、总仓位占比

#### D2. 仓位三三制
- 功能：首次20%、浮盈>3%才加仓、单标的≤40%、总持仓≤40%
- 落点：`Account/Account.py` 内方法

#### D3. 止损止盈
- 功能：
  - -5% 硬止损，次日集合竞价斩仓
  - 5日不涨减半仓
  - 10日不创新高清仓
  - 破箱体次日开盘清仓
- 落点：`Account/Position.py` + 新建 `Account/StopRule.py`

#### D4. 大盘环境联动平仓
- 功能：大盘跌破20日线 → 停止开新仓；持仓联动平仓
- 落点：新建 `ChanModel/MarketEnv.py`，接入持仓循环
- 依赖：大盘指数日线（已有）+ MA20（`mean_metrics`）

#### D5. 回测引擎
- 功能：统一引擎，订单、滑点、手续费、资金曲线
- 落点：新建 `Backtest/Engine.py`
- 依赖：D1-D4

---

### 模块 E：盘中 T+1 二次确认引擎（第三档，最难）

#### E1. 盘中行情轮询层
- 功能：盘中实时拉取快照（akshare `stock_zh_a_spot_em` 或券商 L2）
- 落点：新建 `Realtime/SnapshotPoller.py`

#### E2. 信号状态机
- 功能：
  - Day1 出现放量阳线 → 记录"待确认"信号
  - Day2 14:50 检查是否站稳平台高点 + 缩量至前日60%-80%
  - 满足 → 触发买入；跌破中点 → 取消
- 状态：`PENDING / CONFIRMED / CANCELLED`
- 落点：新建 `Realtime/SignalStateMachine.py`

#### E3. 与日级缠论对接
- 功能：缠论用日K分析结构，盘中确认用实时价
- 落点：`Realtime/` 目录，与 `CChan` 对接

#### E4. 集合竞价执行
- 功能：止损单在次日集合竞价执行
- 落点：`Account/StopRule.py` 扩展

## 七、风险与限制

1. **筹码历史数据**：akshare 只给当前快照，历史演化必须每日落库累积。不累积则"形成>3个月"等判断无法实现。**建议最先建表。**
2. **盘中实时驱动**：当前框架为日级架构，T+1 二次确认需架构改造，是最大工作量。
3. **数据频率限制**：
   - 股东户数季频
   - 大宗交易 T+1 公布
   - 盘中实时快照有调用频率限制，需做限流
4. **akshare 接口稳定性**：第三方接口可能变更，需做容错与重试。
5. **板块/RPS**：本计划暂列为"后续升级"，第一版不实现。
